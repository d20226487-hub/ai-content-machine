# Single — генерация по одному

Раздел `/create` (в меню — **Single**) предназначен для разовой генерации одного результата. Используйте его, когда Вам нужен один заголовок, одна статья, один комментарий.

Если задач много и они однотипны — переходите в **Bulk**.

## Шаги генерации

1. **Выберите промпт** из выпадающего списка. Там доступны все промпты, которые есть у Вас в `/prompts`.
2. **Заполните переменные.** Под промптом появятся поля для каждой `{{variable}}` из его текста. Все поля обязательны — пустых переменных в готовом запросе быть не должно.
3. **Выберите провайдера и модель.**
   - В списке отображаются все включённые администратором провайдеры.
   - У провайдеров без сохранённого API-ключа добавлен суффикс «(нет API-ключа)» и они недоступны для выбора.
   - По умолчанию выбирается первый провайдер с ключом.
4. **Посмотрите предварительный просмотр промпта.** Это итоговый текст, который уйдёт модели — переменные уже подставлены. Так удобно поймать опечатку до запуска.
5. **Нажмите Generate.** Запрос отправляется в выбранную модель.

## Результат

Сгенерированный текст показывается в правой части страницы. Под ним — служебная информация: какая модель отработала, причина завершения (`finish_reason`), длина вывода.

Вид отображения:

- **Rendered** — стандартный режим, рендер HTML в изолированном `<iframe>` (sandbox). Скрипты внутри сгенерированного HTML не выполняются.
- **Raw** — исходный текст без рендера, удобно для копирования.
- **Open in window** — открывает результат в отдельном окне браузера (тоже в песочнице).

Большие результаты (свыше 1 МБ) автоматически переключаются в режим заглушки с кнопкой **Copy** и **Open in window** — чтобы не тормозить интерфейс.

## Сохранение

Кнопка **Save** сохраняет текущую генерацию: текст результата, имя промпта, использованную версию промпта, провайдера, модель и значения всех переменных. Сохранения видны только Вам.

Дальше можно:

- Открыть **Saved generations** (модальное окно со списком сохранённых результатов): просмотр, переименование, удаление, повторное открытие.
- Из ранее сохранённой генерации можно её опубликовать (см. **Публикация: одиночная**), если у Вас есть права.

Подробнее — в разделе «Сохранённые генерации».

## Публикация (admin / manager)

Если Ваша роль позволяет публиковать, рядом с кнопкой **Save** появляется **Publish to…**. Она открывает форму:

- выбор домена;
- выбор «профиля» публикации (если у домена несколько профилей под разные типы записей);
- поля, которые нужно заполнить (заголовок, контент, мета-поля и т. д. — состав зависит от настроек домена);
- язык, если у домена включена многоязычность.

Заголовок предзаполняется именем промпта, контент — сгенерированным текстом. Можно скорректировать перед отправкой.

Запрос на публикацию ставится в очередь — система покажет статус (queued → posting → posted) и в конце вернёт ссылку на опубликованный пост.

## Что бывает с одной и той же генерацией

Откройте сохранённую генерацию через **Saved generations** — Вы увидите её точно в том виде, в каком сохраняли. Под результатом есть блок **Published to**: история публикаций именно этой генерации (если она уже отправлялась куда-то). Можно сразу понять, опубликовано ли уже и куда именно.

## Полезные мелочи

- **Provider и model запоминаются** на сессию: при следующей генерации они подставятся теми же.
- Если переменная пуста или ошибка пришла от провайдера — отобразится подробное сообщение с возможностью раскрыть детали (ошибка от модели, статус-код, заголовки ответа).
- Окно запуска не блокируется во время ожидания — можно перейти на другую вкладку и вернуться.
