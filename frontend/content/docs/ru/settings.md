# Настройки

`/settings` — конфигурация системы. Раздел доступен **только администратору**.

Страница разбита на вкладки; активная вкладка отражается в адресе через `?tab=…`, поэтому ссылку на конкретную вкладку можно скопировать и переслать:

| Вкладка | О чём |
|---|---|
| **Провайдеры** | ключи LLM-провайдеров, модели, лимиты запросов |
| **Публикация** | глобальные лимиты публикации по умолчанию для доменов |
| **Цены** | стоимость токенов provider:model для подсчёта расходов |
| **Бэкапы** | резервные копии базы (расписание, выгрузка в S3) |
| **Корзина** | срок хранения в корзинах (промпты, таблицы, пользователи) |
| **Мозг** | системные промпты для перевода и исправления ссылок |

## Вкладка «Провайдеры»

Конфигурация LLM-провайдеров. В системе зарегистрировано несколько провайдеров, у каждого — карточка с настройками:

- **AI Studio** (Google) — Gemini-модели через Google AI Studio.
- **Vertex AI** (Google Cloud) — корпоративные квоты Gemini через GCP.
- **OpenRouter** — единый шлюз ко многим моделям через OpenAI-совместимый API.
- **GitHub Models** — OpenAI-совместимый эндпойнт GitHub.

### Vertex AI — два режима авторизации

В отличие от остальных провайдеров, Vertex AI работает в двух режимах — карточка сама подстраивается под то, что вы заполнили:

- **Service-account JSON (рекомендуется для прода)** — нужны три поля:
  - **GCP project ID** — например, `my-content-project-123`.
  - **Location** — регион aiplatform, например `us-central1` или `europe-west4`.
  - **Service-account JSON** — целиком вставьте JSON, скачанный из GCP Console (IAM → Service Accounts → Keys → Add Key). У сервисного аккаунта должна быть роль **Vertex AI User** на проекте.
  Бэкенд минтит OAuth2 access-token и обращается к региональному `{location}-aiplatform.googleapis.com`. Полная квота тарифа, без ограничений Express.
- **Vertex Express (API-ключ)** — заполните **только** обычное поле API key выше; project_id, location и SA JSON оставьте пустыми. Бэкенд пойдёт на глобальный `aiplatform.googleapis.com/?key=…`. Удобно для пробы, но квоты тугие.

JSON сервисного аккаунта при сохранении шифруется Fernet и обратно в UI не показывается — кнопка **Clear** под полем стирает все три поля сразу. Тест-коннект использует сохранённые поля (если поменяли JSON — сначала сохраните, потом тестируйте).

### Включение провайдера

Тумблер **Enabled** — включает или выключает провайдера. Только включённые провайдеры показываются пользователям при выборе в Single и Bulk.

Если у провайдера **нет API-ключа**, в выпадающих списках Single и Bulk он будет показан, но с пометкой «(нет API-ключа)» и недоступен для выбора.

### API-ключ

Ключ хранится в зашифрованном виде (Fernet). Поле ввода:

- **Пустое** при загрузке — это нормально, текущий ключ не показывается из соображений безопасности.
- Введите новый ключ и сохраните — он перезапишет старый.
- Введите пробел или удалите ключ — будет очищен (станет «нет API-ключа»).

### Модели

Для каждого провайдера задаются:

- **Default model** — модель по умолчанию для генерации.
- **Prompt-creation model** — модель для AI-assist при создании промптов. Обычно стоит дешёвая или быстрая модель.
- **Available models** — список доступных пользователю моделей (через запятую). В Single и Bulk пользователь увидит этот список в выпадающем меню.

### Test connection

Кнопка **Test connection** отправляет минимальный пробный запрос к провайдеру с использованием текущего ключа и модели по умолчанию. Возвращает успех/неудачу, латентность, образец вывода и текст ошибки, если что-то не так. Удобный способ убедиться, что ключ валиден и квоты не исчерпаны, без перехода в Single.

### Лимиты на провайдера

У каждой LLM-модели есть свои ограничения. Чтобы не упереться в 429 от провайдера, в системе есть **лимиты**:

- **Requests per minute (RPM)** — суммарный лимит запросов в минуту.
- **Max concurrency** — максимум параллельных запросов одновременно.
- **Batch size** — размер пакета (используется массовой генерацией).
- **Inter-request delay (ms)** — пауза между запросами.
- **Retry max attempts** — сколько раз повторять при 429/5xx.
- **Backoff base / jitter (ms)** — базовая задержка перед повтором и случайный разброс, чтобы избежать «стаи» одновременных повторов.
- **Respect Retry-After** — учитывать ли заголовок `Retry-After` в ответе провайдера. Если включено, при 429 система ждёт ровно столько, сколько просит провайдер, а не свой backoff.

Все ограничения работают на уровне Redis: даже если несколько Celery-воркеров одновременно дёрнут провайдера, общий счётчик не превысит лимит. Контроль атомарный (Lua-скрипт), без гонок.

Что задавать:

- **RPM** — обычно из тарифа провайдера.
- **Max concurrency** — у Gemini хорошо работает 4–8, у GPT-4 / Claude — 1–2 на ключ.
- **Inter-request delay** — нужен только если конкретный провайдер часто отдаёт 429 даже при низком RPM.

### Если провайдер «не виден» пользователям

Проверьте по списку:

1. **Enabled = true?**
2. **API key сохранён?** (если нет — провайдер появится в списке с пометкой «(нет API-ключа)»)
3. **Default model** не пуст?
4. **Available models** содержит хотя бы одну модель?

Если все четыре пункта — да, провайдер появится в Single и Bulk без перезапуска.

## Вкладка «Публикация»

Глобальные значения по умолчанию для публикации (RPM, concurrency и пр.). Они применяются ко всем доменам в `/publish/domains`, у которых соответствующие поля оставлены пустыми, — домен может переопределить любое из них у себя.

См. раздел «Публикация: домены» — там описано, как лимиты домена наследуются от глобальных.

## Вкладка «Цены»

Стоимость токенов для подсчёта расходов. Каждая строка — пара **provider:model** и цена в **USD за 1 000 000 токенов** отдельно на вход и выход.

- **+ Добавить строку** — новая пара. Заполните код провайдера (например, `ai_studio`), модель (например, `gemini-2.5-flash`) и цены; дробные значения допустимы (`0.075`, `0.30`).
- **Сохранить** — перезапись целиком: убрали строку — цена для этой пары очищается.

Стоимость считается **в момент записи события генерации**, поэтому правки здесь влияют только на новые генерации — исторические суммы не пересчитываются. Итоговые расходы по пользователям видны в колонке **Расходы** на `/users` (см. «Пользователи и роли»).

## Вкладка «Бэкапы»

Резервные копии базы. Ежедневный `pg_dump` запускается в выбранное время (по умолчанию 03:00 UTC); дампы всегда сохраняются локально на сервере приложения и при желании выгружаются во внешнее хранилище.

- **Расписание** — включить/выключить автоматические копии и задать час запуска (UTC). Изменения подхватываются со следующего запуска, перезапуск не нужен.
- **Куда сохранять** — опционально включить выгрузку в любое **S3-совместимое хранилище** (AWS S3, MinIO, Garage, Backblaze B2 и т. п.): эндпойнт, регион, бакет, префикс ключа, access key / secret key. Secret шифруется и обратно не показывается. Отдельные сроки хранения для локальных копий и для S3.
- **Проверить подключение** — пробная проверка доступа к S3.
- **Запустить сейчас** — внеплановая копия в один клик.
- **Последние запуски** — таблица: начало, статус, размер, триггер, ключ S3, ошибка.

## Вкладка «Корзина»

Срок хранения в корзинах перед безвозвратной автоочисткой — отдельно для **промптов**, **bulk-таблиц** и **пользователей**. По умолчанию 50 дней; `0` отключает автоочистку (объекты лежат в корзине, пока их не удалят руками). Проверка идёт раз в сутки фоновой задачей.

Подробности по каждой корзине — в разделах «Bulk», «Промпты» и «Пользователи и роли». Важное исключение: **администраторы автоматически из корзины не вычищаются** — только ручное «Удалить навсегда».

## Вкладка «Мозг»

«Мозг» — это редактируемые администратором **системные промпты**, которые питают on-demand действия в остальном приложении. Сейчас их два:

### Промпт для перевода

Управляет кнопкой **Перевести** в редакторе ячеек bulk-таблиц (и на других экранах — см. «Перевод контента»).

- **Системный промпт** — как переводить. Плейсхолдер `{{target_language}}` подставляется выбранным языком; значение ячейки уходит моделью как сообщение пользователя.
- **Язык перевода по умолчанию** — двухбуквенный код (например, `ru`), который подставляется по умолчанию, пока пользователь не выбрал свой.
- **Провайдер ИИ для перевода** — провайдер и модель. Пусто = первый включённый провайдер и его модель по умолчанию.

### Промпт исправления ссылок

Используется кнопкой **Исправить ИИ** в инструменте «Проверка ссылок» (см. «Bulk: инструменты контента»). Имея список ожидаемых ссылок и найденные проблемы, модель вставляет недостающие ссылки, исправляет опечатки и удаляет выдуманные — меняя только ссылки и больше ничего. Настраиваются системный промпт и провайдер/модель.

## Безопасность ключей

- Ключи шифруются Fernet-ключом, который читается только бэкендом.
- В журналах и `/errors` ключи маскируются: даже если провайдер вернул ошибку с куском авторизационного хедера в теле — он будет урезан перед сохранением.
- В UI ключ никогда не показывается обратно после сохранения.
- Поддерживается ротация ключа Fernet (`MultiFernet`): можно ввести новый ключ как основной, оставить старый для расшифровки старых записей и постепенно перешифровать всю базу.
