# Bulk — таблицы массовой генерации

Раздел `/library` (в меню — **Bulk**) — это таблицы. Каждая строка — отдельная задача, каждая колонка — либо вход (переменные), либо выход (генерируемый текст). Используйте Bulk, когда нужно получить десятки или сотни результатов по одной и той же логике.

## Список таблиц

`/library` устроен как `/prompts`: папки сверху, таблицы — карточками. Поиск, фильтр по папкам, пагинация — всё работает так же.

- **+ Новая папка** — создаёт папку. Папки в Bulk **плоские**: вложить одну папку в другую нельзя.
- **+ Новая таблица** — создаёт пустую таблицу. Дайте имя и при желании опишите назначение.
- **Move** на карточке — перенести таблицу в другую папку.
- **Duplicate** — копия таблицы со всеми колонками (без значений ячеек).

### Кто что видит

- **content_generator** видит только свои таблицы.
- **admin** и **manager** видят все таблицы. Удалять чужие таблицы может только администратор; менеджеры могут открывать и править, но не удалять.

## Внутри таблицы

Откройте таблицу — увидите редактор:

- **Колонки** идут слева направо. У каждой колонки есть тип: **input** (хранит значения переменных) или **output** (туда генерируется текст).
- **Строки** добавляются кнопкой **+ Row**. Можно добавить пакетом — система предложит ввести количество.
- **Ячейки** редактируются двойным щелчком: открывается окно с вкладками **Edit** и **Preview**.

### Колонки

Чтобы добавить колонку — кнопка **+ Column** в правой части шапки. Над каждой колонкой в шапке при наведении появляются три кнопки:

- **⚙ Configure** — настроить колонку.
- **⇄ Kind** — переключить input ⇄ output.
- **× Delete** — удалить колонку.

Переименовать колонку — двойной клик на её имени.

#### Настройка output-колонки

В output-колонке можно задать:

- **Промпт** — какой шаблон использовать для генерации.
- **Сопоставление переменных** — каждой `{{variable}}` промпта указывается input-колонка, откуда брать значение для конкретной строки.
- **Провайдер и модель** — необязательно. Если не задано — берётся первый включённый провайдер с ключом. Полезно, например, отдать дешёвой модели заголовки, а дорогой — основной текст.
- **Макс. выходных токенов** — необязательный потолок длины ответа для этой колонки. Пусто = глобальное значение из «Настройки → Генерация». Поднимите для длинных статей, снизьте для заголовков и мета-описаний. Если модель упрётся в потолок, ответ придёт **обрезанным** (см. ниже).
- **Grounding (веб-поиск)** — необязательно; только для **Vertex AI + Gemini**. Включите «Google Search», чтобы модель искала тему в вебе и приводила источники. Подробнее — раздел «Grounded-исследование».

### Ячейки

Состояние ячейки видно по цвету и иконке:

- **empty** — пусто.
- **manual** — заполнено вручную.
- **generating** — сейчас генерируется.
- **generated** — успешно сгенерировано.
- **failed** — ошибка. Кликните по ячейке — увидите подробности и кнопку **Retry this cell**.

Отдельный случай — **обрезанная** ячейка: статус `generated`, но в углу жёлтый бейдж **обрезано**. Модель упёрлась в лимит выходных токенов, поэтому текст неполный. Поднимите «Макс. выходных токенов» у колонки (или глобально в «Настройки → Генерация») и перегенерируйте.

Двойной клик по ячейке открывает редактор. Edit — текстовое поле, Preview — рендер HTML-результата (для output-колонок). В редакторе также виден **счётчик слов** результата. В режиме Preview у заполненной ячейки есть кнопка **Перевести** — параллельный перевод значения (см. «Перевод контента») — и возможность создать **публичную ссылку на ячейку**: токенизированный URL, по которому значение открывается без входа в систему. Ссылку можно отозвать — после этого она перестаёт работать.

У **grounded**-ячейки (колонка с включённым веб-поиском) в редакторе под текстом виден блок **Источники (N)** со ссылками, которые процитировала модель, и строка **Искали: …** с запросами (см. «Grounded-исследование»).

## Автосохранение

Изменения сохраняются автоматически с задержкой ~600 мс после последнего ввода. В правом верхнем углу видно состояние: **Saving…** или **Saved**.

Можно спокойно переключаться между ячейками и закрывать вкладку — данные сохранятся.

## Импорт и экспорт

Кнопка **Import CSV** загружает значения в таблицу: первая строка — заголовки, дальше данные. Если заголовок совпадает с именем существующей колонки — данные уйдут туда; новые имена создадут новые input-колонки.

В окне импорта есть выпадающее меню **Download sample ▾** — четыре готовых шаблона CSV под основные сценарии публикации: WordPress (один сайт / несколько сайтов) и Custom CMS (один сайт / несколько сайтов). Удобно, если вы только начинаете и хотите увидеть, какие колонки в каком случае нужны. Для Custom CMS колонки в шаблоне отражают плейсхолдеры `body_template` существующего тестового домена — на вашем домене они могут отличаться.

**Export CSV** скачивает текущее состояние таблицы целиком. Экспорт больших таблиц идёт фоновой задачей с индикатором прогресса, потом файл скачивается.

## Обновить таблицу из CSV

Кнопка **Update table** в шапке таблицы — это **не** импорт. Импорт добавляет строки; обновление правит ячейки **уже существующих** строк:

- **Источник** — файл CSV или вставленный текст.
- **Сопоставление** — какая колонка данных идёт в какую колонку таблицы.
- **Как сопоставлять строки**:
  - **По ключу** — строки матчатся по значению ключевой колонки (например, slug или домен); порядок в файле не важен.
  - **По порядку** — N-я строка данных обновляет N-ю строку таблицы.
- **Пропускать пустые** — пустые значения в источнике не затирают уже заполненные ячейки.

## Запуск генерации

В верхней части таблицы есть кнопка **Generate…**. Она открывает окно очереди генерации:

- **Колонки для запуска** — чекбоксы по всем output-колонкам с заданным промптом. За один прогон можно запустить сразу несколько колонок; колонки без промпта показаны неактивными.
- **Строки**:
  - **All** — все строки.
  - **Selected** — выделенные чекбоксами в таблице.
  - **Range** — диапазон по позиции, например `1–50`.
- **Какие ячейки**:
  - **Только пустые** (по умолчанию) — пропустить уже сгенерированные.
  - **Только с ошибкой** — повторить только упавшие (`failed`).
  - **Только обрезанные** — повторить те, что упёрлись в лимит токенов и пришли неполными. Сначала поднимите «Макс. выходных токенов», иначе их снова обрежет.
  - **Все ячейки (перезапись)** — перегенерировать всё, затирая готовое.
- **Переопределить провайдера/модель** — галочка: задать один провайдер и модель на весь прогон, игнорируя настройки отдельных колонок. По умолчанию выключено.
- Внизу — строка «Будет сгенерировано N ячеек…», которую сервер пересчитывает под выбранные фильтры.

После подтверждения запросы становятся в очередь Celery и обрабатываются параллельно с учётом лимитов провайдера. Сверху идёт баннер прогресса; таблица каждые 1.5 секунды опрашивает статус, ячейки переходят из **generating** в **generated** или **failed** на глазах.

Если у какой-то из выбранных колонок в промпте есть **несопоставленные переменные**, окно очереди подсветит их и **не даст запустить** прогон, пока Вы не сопоставите каждую переменную с колонкой (иначе модель получит промпт с «сырыми» `{{плейсхолдерами}}`).

## Grounded-исследование (веб-поиск)

Output-колонку можно пометить как **grounded**: при генерации модель сначала ищет тему в вебе через **Google Search** и приводит **источники**. Полезно, когда нужны свежие факты, а не только «память» модели — обзоры, новости, тексты со ссылками.

**Как включить.** В настройке output-колонки выберите **Grounding → Google Search — исследовать тему**. Контрол доступен только для провайдера **Vertex AI** с моделью **Gemini**; для остальных провайдеров он выключен, а при смене провайдера с Vertex — сбрасывается. Сервер тоже это проверяет: попытка включить grounding для не-Vertex (или Claude) вернёт ошибку.

**Промпт остаётся обязательным.** Grounding не заменяет промпт — он лишь добавляет модели инструмент веб-поиска поверх Вашего промпта. Поэтому формулируйте промпт так, чтобы он опирался на свежие данные, например: «Исследуй тему {{topic}} и напиши…».

**Источники.** У grounded-ячейки в редакторе под текстом появляется блок **Источники (N)** — кликабельные ссылки, которые процитировала модель, и строка **Искали: …** с поисковыми запросами. Это provenance-ссылки Vertex: они живут ~30 дней и являются записью «что модель смотрела», а не постоянным хранилищем цитат.

**Кэш (экономия).** Grounded-вызов оплачивается за каждый запрос, поэтому его результат **мемоизируется** — кэшируется по хэшу «отрендеренный промпт + модель + источник grounding». Повторная генерация той же ячейки (или другая строка с теми же входными данными) в течение **30 дней** берёт результат из кэша: **без нового вызова провайдера и без доплаты**. Не-grounded генерации кэш не трогает. По истечении срока запись читается как «промах», и генерация идёт заново (ссылки Vertex к этому моменту всё равно протухают).

**Доплата за grounding.** Каждый *оплаченный* grounded-запрос добавляет фиксированную **доплату** (по умолчанию $0.035 за запрос — тариф Google $35 за 1000; настраивается). Она пишется **отдельным событием расхода** (`grounding`) и видна в блоке «Стоимость генерации»; кэш-попадания доплату не создают. В окне очереди перед запуском показывается оценка «**N с поиском — до $X доплаты за Google Search (повторы из кэша бесплатны)**» — это максимум, кэш только уменьшает его.

## Уведомление об ошибках и обрезках

Когда в таблице есть ячейки, требующие внимания, над сеткой появляется цветной баннер. Счёт идёт **по всей таблице**, а не только по текущей странице:

- **✗ N ячеек с ошибкой генерации** (красный) — запрос упал. Баннер показывает, в каких колонках, и кнопку **Retry failed (N)**, которая открывает очередь, уже настроенную на режим «Только с ошибкой» и эти колонки.
- **⚠ N ячеек обрезано** (жёлтый) — ответ упёрся в лимит выходных токенов. Показаны затронутые колонки и кнопка **Retry truncated (N)**; перед повтором поднимите «Макс. выходных токенов».

Так сразу видно, где применять «Retry failed» или «Retry truncated». Баннер сам исчезает, когда чинить нечего, и обновляется после завершения прогона.

> **Важно про старые тексты.** Баннер читает текущее состояние ячеек. **Ошибки** он находит для любых ячеек — когда бы их ни сгенерировали. А вот **обрезки** видны только для генераций, сделанных с момента появления учёта лимитов вывода: раньше причина остановки модели не сохранялась, и «молча» обрезанный текст неотличим от завершённого. Такие старые обрезки баннер не пометит (эти данные восстановить нельзя) — перегенерируйте ячейку, и обрезка начнёт отслеживаться.

## Стоимость генерации

Под шапкой таблицы есть сворачиваемый блок **Стоимость генерации**. Считается по запросу (агрегат по событиям расхода):

- **Итог** — суммарные траты на генерацию таблицы в USD, с разбивкой по колонкам (стоимость, ячейки, число вызовов, токены). Расход **накопительный**: повторы и перегенерации тоже учитываются — это «сколько таблица стоила», а не «сколько стоит текущий текст».
- **ИИ-инструменты** — отдельный блок: расход на ИИ-проходы поверх генерации (**перевод**, **ИИ-исправление ссылок**). Показан отдельно и **не входит** в сумму генерации выше. Звёздочка у строки — вызовы, добавившие $0 (не задана цена провайдера:модели, либо вызов был до появления учёта токенов).
- **Доплата за grounding** — фиксированная доплата за каждый оплаченный веб-поиск (Google Search) в grounded-колонках, отдельными событиями `grounding`. Кэш-попадания её не создают. Подробнее — «Grounded-исследование».
- Если у пары провайдер:модель не задана цена, такие вызовы считаются как $0 — реальная сумма выше. Цену задаёт администратор в «Настройки → Цены» (применяется к будущим генерациям).

## Управление видом таблицы

Эти настройки сохраняются в Вашем браузере — каждая таблица помнит их отдельно:

- **Ширина колонок** — потяните за правый край шапки колонки.
- **Высота строк** — Compact / Default / Comfortable / Tall.
- **Размер страницы** — 5 / 10 / 20 / 50 / 100 / 200 / 500 / 1000 строк.
- **Пагинация** — снизу таблицы.

## Полезные действия с выделением

Если выделить несколько строк чекбоксами, появится панель действий:

- **Clear values** (красная кнопка) — очищает значения во всех ячейках выделенных строк. Сами строки при этом остаются.
- Удаление строк — крестик в начале строки или у каждой строки в режиме просмотра.

Колонки удаляются индивидуально, **массового удаления колонок нет**.

## Инструменты контента

Под сеткой таблицы есть блок **Инструменты контента** — инструменты, работающие сразу по всей таблице: **Найти и заменить**, **Проверка ссылок** (+ ИИ-исправление), **Структура и форматирование** и **Нормализация**. У каждого своя страница, история запусков и откат. Подробно — в разделе «Bulk: инструменты контента».

## Корзина (Trash)

Удаление таблицы — теперь **soft-delete**: она попадает в Корзину, а не пропадает безвозвратно. Это защита от случайных кликов по красной кнопке.

- На странице `/library` сверху появляется ссылка **Корзина (N)**, когда в ней есть таблицы.
- На `/library/trash` — список удалённых таблиц: имя, размер (колонки × строки), кто и когда удалил.
- Кнопки по каждой строке:
  - **Просмотр** — открывает таблицу в режиме read-only (первые 100 строк). Редактировать нельзя — для этого нужно сначала восстановить.
  - **Восстановить** — возвращает таблицу в активный список. Если папка, в которой она лежала, успели удалить — таблица восстанавливается без папки.
  - **Удалить навсегда** — безвозвратное удаление со всеми колонками, строками, ячейками и связанными прогонами публикации.
- Множественные действия — чекбоксами слева плюс кнопки **Восстановить выбранные** / **Удалить выбранные** / **Очистить корзину** сверху.
- Прямой URL `/library/<id>` для удалённой таблицы **не работает** (404). Открыть её можно только из Корзины.

### Защита от удаления во время публикации

Если по таблице идёт активный прогон Bulk Publish (статус `queued`, `running` или `paused`), удалить её нельзя — будет ошибка 409 с предложением сначала отменить или дождаться окончания прогона на `/publish/runs`.

### Автоочистка корзины

По умолчанию таблицы лежат в Корзине **50 дней**, потом удаляются безвозвратно. Срок настраивается администратором на `/settings` → **Срок хранения корзины таблиц**. Значение `0` отключает автоочистку — таблицы остаются в Корзине, пока их не удалят руками. Проверка идёт раз в сутки фоновой задачей (03:15 UTC); если нужно очистить раньше — кнопка **Очистить корзину** на `/library/trash`.

## Если упали ячейки

Откройте такую ячейку — будет подробная ошибка, та же, что в журнале `/errors`. Возможные причины:

- кончились квоты у провайдера (429);
- сетевая ошибка или таймаут (5xx);
- неправильно настроено сопоставление переменных (например, в input-колонке пусто).

Кнопка **Retry this cell** попытается ещё раз без обращения к Generation Queue — это быстрый путь для одной упавшей ячейки. Для нескольких — лучше перезапустить через **Generate…** с фильтром **Only failed**.
