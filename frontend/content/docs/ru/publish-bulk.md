# Публикация: массовая

Массовая публикация — это отправка содержимого многих строк bulk-таблицы в один домен за один запуск. Доступна админам и менеджерам.

## С чего начать — пример таблицы

Если ещё не знаете, какие колонки нужны под ваш сценарий — на `/library` в окне **Import CSV** есть выпадающее меню **Download sample ▾** с четырьмя готовыми шаблонами: WordPress (один сайт / несколько сайтов) и Custom CMS (один сайт / несколько сайтов). Скачайте подходящий, заполните контентом, импортируйте — получите таблицу в правильной форме, и шаг сопоставления полей ниже сделается за пару кликов.

## Откуда запускается

Откройте Вашу bulk-таблицу в `/library/[id]`. В верхней панели есть кнопка **Publish bulk…** рядом с **Generate…**. Она доступна, только если в таблице есть колонки с готовым контентом.

## Окно настройки публикации

Откроется модальное окно **Bulk publish**. Сверху — переключатель режима: **Single** (всё в один сайт) или **Multi** (каждая строка → свой сайт). По умолчанию открывается Single. Дальнейшие шаги одинаковые, отличается только шаг 1 — про режимы ниже.

### 0. Create или Update — что делаем с постами

Под переключателем Single / Multi есть второй сегмент: **Create / Update**. Работает в обоих режимах.

- **Create** (по умолчанию) — каждая строка создаёт новый пост в WP. Поведение, которое было раньше.
- **Update** — каждая строка обновляет уже существующий пост. Для каждой строки система ищет пост в WP, потом отправляет PATCH с замаплеными полями.

Когда выбран **Update**, появляются дополнительные поля:

- **Look up post by** — `Post ID` (числовой ID поста WordPress) или `Slug` (slug поста).
- **Lookup column** — какая колонка таблицы содержит этот идентификатор для каждой строки. Для `Slug` принимаются как «голый» slug (`my-post`), так и полные URL (`https://site.com/category/my-post/`) — система сама вытащит последний сегмент пути. Поиск идёт по постам любых статусов (publish / draft / pending / private), пока у учётки хватает прав.

Если ячейка пустая для замапленного поля — это поле **не отправляется** в PATCH, и на стороне WP остаётся прежнее значение. То есть «пустая ячейка = не трогать». Маппьте только те колонки, которые хотите перезаписать.

Сообщения об ошибках:

- `Existing post not found on {domain} (id=…/slug=…)` — пост по такому id/slug не найден (или нет прав).
- `Update lookup column is empty for this row` — ячейка в lookup-колонке пустая.
- `Update mode is supported only for WordPress domains` — выбран Custom-CMS-домен. В single-режиме блокируется при старте; в multi-режиме упадут только Custom-строки, WP-строки уедут нормально.

Update работает и в Single, и в Multi. В Multi определяющая домен колонка может содержать сайты разных типов — WP-строки обновятся, не-WP упадут с понятной ошибкой. **Rerun failed** на терминальном прогоне перезапустит только упавшие строки, переиспользуя те же lookup и operation.

### 0.1 «Что делать с дубликатами по slug» (только в Create-режиме)

Когда выбран **Create**, есть дополнительный переключатель **Если slug уже занят**:

- **Create anyway** *(по умолчанию)* — текущее поведение. WP сам добавит суффикс (`canada` → `canada-2`), если slug совпал.
- **Skip** — перед каждой строкой система проверяет WP, есть ли пост с таким slug. Если есть — строка попадает в статус `skipped`, новый пост не создаётся. Удобно, чтобы перезапустить генерацию без двойной публикации.
- **Update existing** — upsert: если пост с таким slug существует, PATCH-им его (так же, как в Update-режиме — пустые ячейки не трогают существующие поля). Если нет — публикуем новый.

Что нужно знать:

- **Колонка с `slug` обязана быть в маппинге.** Без неё проверять нечего (WP сгенерит slug из title уже на своей стороне). Если slug не замаплен — кнопка серая и появляется подсказка.
- **Проверка по языку.** На сайтах с Polylang/WPML мы передаём `?lang=` в запрос. То есть EN `canada` НЕ помешает создать новый RU `canada` — это разные посты в разных языковых пространствах.
- **+1 GET на строку.** Прогон становится примерно в 2× медленнее. На фоне Cloudflare WAF и прочего лимитирования это всё ещё приемлемо, но имейте в виду.
- **Rerun failed** не подхватывает `skipped` строки — это была явная команда «пропустить».

### 1а. Single — один домен на весь прогон

- **Domain** — куда публиковать.
- **Profile** (только WP) — какой «рецепт» использовать.

Если для этой комбинации (таблица × домен × профиль) Вы уже публиковали раньше, система **запомнила сопоставление полей** и подставит его автоматически. Внизу окна виден переключатель **Remember mapping** (включён по умолчанию) и ссылка **Clear saved mapping**.

### 1б. Multi — несколько сайтов в одном прогоне

Этот режим раньше отсутствовал: можно было публиковать только в один WP-сайт за прогон. Теперь в одной bulk-таблице можно держать строки для разных доменов и публиковать их одним нажатием.

В режиме **Multi** вместо выпадающих списков «Domain» и «Profile» Вы указываете **колонки таблицы**, в которых лежат эти значения:

- **Domain column** — колонка с именами доменов (как они называются в `/publish/domains`). Совпадение **терпимое**: схема (`http://`/`https://`), `www.` и завершающий слэш игнорируются — ячейка `https://example.com/` найдёт домен `example.com`. Если «голое» имя не нашлось, пробуется точное значение ячейки (на случай дружественных, не-доменных имён).
- **Language column** *(опционально)* — колонка с языком для каждой строки. Доступна и в Single, и в Multi — в обоих режимах ячейка читается, нормализуется (нижний регистр + trim, `EN`, `en`, ` Ru ` → `en`/`ru`) и сверяется со списком языков целевого домена (в Single — выбранного, в Multi — резолвленного из домен-колонки). **Пустая ячейка → строка падает**: если включаете эту колонку — заполните её во всех строках. Полезно, когда в одной таблице смешаны посты под разные языки (даже на одном сайте) или под разные языки разных сайтов.
- **Profile column** *(опционально)* — колонка с именем профиля (рецепта) для каждой строки. Если у домена несколько профилей и эта колонка пуста — строка упадёт с ошибкой «Profile column is empty for this row».

Что происходит дальше:

- Перед публикацией каждой строки система **резолвит цель**: читает домен из ячейки, ищет его по имени, проверяет профиль.
- Если домен из ячейки не найден — строка падает со статусом `failed` и причиной (`Domain not found: "site9.com"`). Это не валит остальные строки.
- **Custom CMS в multi-режиме не поддерживается** (нужно обрабатывать строки по одному). Если в ячейке оказался домен типа Custom — строка упадёт с понятной ошибкой и предложением запустить её через Single.
- Сохранённое сопоставление полей (Remember mapping) для multi-режима **общее на таблицу**: вне зависимости от того, в какие домены поедут строки, набор колонок и back-fill будет один и тот же.

Внизу окна — живое превью: «Будет опубликовано N строк в M доменов» с топом по доменам.

### Нормализация значений для Custom CMS

Перед отправкой в **Custom CMS** значения приводятся к ожидаемому флотом виду (на сами ячейки таблицы это не влияет — нормализуется только то, что уходит в запрос):

- **slug** — в нижнем регистре (`/Where-To-Watch/` → `where-to-watch`), плюс прежняя обрезка слэшей и метка домашней страницы (`/`, `/es/` для языка `es` → `home`).
- **язык** — простой двухбуквенный код в нижнем регистре (`EN` → `en`); региональные/скриптовые формы (`pt-BR`, `zh-Hant`) не трогаются.

Для **WordPress** это поведение **не применяется** — WP сам нормализует slug (`sanitize_title`), а регистр языка может быть значимым.

Чтобы привести значения к нужному виду **в самой таблице** (для любой CMS, а не только при отправке), используйте инструмент **Нормализация** под сеткой таблицы.

### 2. Сопоставление полей с колонками

Для каждого поля профиля (или плейсхолдера в body-шаблоне Custom CMS) Вы выбираете колонку bulk-таблицы, из которой брать значение для каждой строки.

Колонки можно сопоставлять «потяните вниз» — выберите колонку для первого поля, и система предложит автозаполнение для остальных по похожим именам.

### 3. Обратная запись (back-fill)

Опционально:

- **post_id_target** — колонка, в которую записать ID опубликованного поста.
- **post_url_target** — колонка, в которую записать URL опубликованного поста.

Эти колонки должны быть input-типа. Они нужны для двух вещей:

- **Аудит** — Вы видите прямо в таблице, что строка уже опубликована и куда.
- **Фильтр «Only unpublished»** — система определяет «уже опубликованные» строки именно по заполненной колонке `post_id_target`.

### 4. Фильтры

- **Строки**:
  - **All** — все строки таблицы.
  - **Selected** — только выделенные через чекбоксы.
  - **Range** — диапазон, например `1–100`.
- **Cell filter**:
  - **All** — все строки попадают в публикацию.
  - **Only unpublished** — только те, где `post_id_target` пуст.
  - **Only failed** — только те, у которых предыдущий запуск завершился ошибкой.

Внизу видно живое превью: «Будет опубликовано N строк».

### 5. Старт

Нажмите **Publish**. Окно закроется, Вас перебросит на `/publish/runs/[id]` — страницу прогона.

## Страница прогона

`/publish/runs/[id]` показывает текущий запуск:

- бейдж режима в заголовке — **single** или **multi**;
- общий прогресс (`done` / `failed` / `skipped` / `total`);
- прогресс-бар и автообновление каждые 2 секунды;
- таблицу всех `publish_jobs` этого прогона со статусом, ID и URL поста, ошибкой;
- в multi-режиме — дополнительные колонки **Domain** и **Profile** в этой таблице, например:

  | Row | Domain      | Profile  | Status     | Post ID | URL                   | Error                          |
  | --- | ----------- | -------- | ---------- | ------- | --------------------- | ------------------------------ |
  | 17  | site1.com   | Article  | ✓ posted   | 1234    | site1.com/foo         | —                              |
  | 18  | site1.com   | Article  | ✗ failed   | —       | —                     | WP returned 401                |
  | 19  | site2.com   | Page     | ✓ posted   | 88      | site2.com/foo         | —                              |
  | 20  | (unknown)   | (unknown)| ✗ failed   | —       | —                     | Domain "site9.com" not found   |

- в multi-режиме над таблицей появляется блок **by-domain summary** — сколько строк ушло в каждый домен и сколько из них упало; рядом с каждым доменом кнопка **Filter** фильтрует таблицу ниже на одну строку без перезагрузки;
- фильтры над таблицей: по **Domain** (в т.ч. псевдо-значение «(unresolved)» — для строк, где домен так и не разрешился) и по **Status** (`posted` / `failed` / `posting`);
- кнопки **Pause**, **Resume**, **Cancel**.

### Pause / Resume / Cancel

- **Pause** — все ещё не запущенные строки помечаются как пропущенные. Уже запущенные дойдут до конца.
- **Resume** — продолжает с тех строк, что не дошли до терминального статуса. Уже опубликованное и упавшее **не публикуется повторно**.
- **Cancel** — то же самое, но без возможности возобновить.

### Rerun failed

Когда прогон завершился, если есть упавшие строки — появляется кнопка **Rerun failed**. Она **не создаёт новый прогон**: тот же самый прогон возвращается в статус `running`, счётчик `failed` уменьшается на число повторяемых строк, а упавшие строки заново ставятся в очередь. Старые `publish_jobs` со статусом `failed` остаются для аудита — каждая повторная попытка добавляет новую запись в `publish_jobs`.

Если ретрай тоже упал — кнопка появится снова, и так до тех пор, пока всё не опубликуется или Вы не сдадитесь.

## Список всех прогонов

`/publish/runs` (в меню **Publish → Bulk Runs**) — список всех когда-либо запущенных массовых публикаций. Видно домен, таблицу, статус, прогресс, кто запустил, когда. Здесь же можно открыть любой прошлый прогон и посмотреть детали.

### Удаление прогонов

В правом верхнем углу страницы — кнопка **Clear completed**: удаляет все прогоны в терминальном статусе (`done` / `failed` / `cancelled`) вместе с их `publish_jobs`. Прогоны в работе (`running`, `queued`, `paused`) не трогаются — их сначала надо **Cancel**.

В каждой строке списка справа есть **×** — удаляет один прогон (тоже только в терминальном статусе) вместе с его `publish_jobs`. Действие подтверждается окном `confirm` и необратимо.

## Лимиты и параллелизм

Прогон уважает лимиты домена. Например, если стоит `max_concurrency = 2` и `RPM = 30` — параллельно будет идти максимум 2 публикации, и не быстрее 30 в минуту. Воркеров под массовую публикацию настроено 8 — этого хватает с большим запасом, реальное ограничение всегда сверху от Ваших настроек домена.

## Кэш медиа

Если несколько строк ссылаются на одну и ту же картинку (`media_url`), она загрузится в WordPress только один раз и переиспользуется по `media_id`. Подробнее — в разделе «Публикация: домены».

## Идемпотентность

В системе предусмотрено несколько уровней защиты от двойной публикации:

- **При планировании** — уже отправленные и упавшие строки исключаются из очередного прогона.
- **При выполнении** — даже если Celery вдруг переотправит ту же задачу (например, из-за рестарта воркера), задача проверит, нет ли уже активной или завершённой публикации для этой строки в этом прогоне.

На практике дубль-постов не бывает, даже если воркер падал в середине прогона.

## Autotool — третий режим публикации (публичный CSV)

Кроме «пуша» в WordPress/Custom CMS есть третий режим — **Autotool**. Здесь наоборот: таблица отдаётся как **публичный CSV**, который забирает внешний Autotool-прокси и сам раскладывает контент по сайтам.

Кнопка **Autotool** — в верхней панели таблицы, рядом с **Generate** и **Publish**:

- **Включить** — по клику всплывает предупреждение, что таблица станет **публично доступной без авторизации**. После подтверждения появляется ссылка вида `…/autotool/<токен>.csv` с неугадываемым токеном и кнопка **Copy CSV link**.
- **Выключить** (**Remove from Autotool**) — с подтверждением; публичная ссылка **сразу перестаёт работать** (токен сбрасывается).

Список всех таблиц, отданных в Autotool, и запуски прокси — на странице **Publish → Autotool** (`/publish/autotool`).

> Ссылка открывает актуальные данные таблицы без входа в систему. Отдавайте в Autotool только то, что можно показывать публично, и убирайте таблицу из Autotool, когда прокси отработал.

## Если что-то идёт не так

- **Много 401 / 403** — проверьте авторизацию в `/publish/domains`, особенно для WP-app-password.
- **Много 429** — снизьте RPM или max_concurrency у домена.
- **Картинки не загружаются** — проверьте `/errors`. Чаще всего проблема в URL изображения (приватный/устаревший).
- **Все строки в `skipped`** — обычно фильтр `Only unpublished` сработал на уже отработавшую таблицу. Поменяйте фильтр на **All** или очистите `post_id_target` в нужных строках.
- **Multi: `Domain not found: "..."`** — значение в ячейке колонки Domain не совпадает ни с одним именем в `/publish/domains`. Проверьте опечатки и пробелы; имена сравниваются точно (case-sensitive).
- **Multi: `Profile "X" not found for domain "Y"`** — у этого домена в `/publish/domains` нет профиля с таким именем. Откройте редактирование домена и сверьте список профилей.
- **Multi: `Multi-site publish to Custom CMS is not supported`** — домен типа Custom CMS попал в multi-прогон. Запустите его отдельно через Single для этого домена.
