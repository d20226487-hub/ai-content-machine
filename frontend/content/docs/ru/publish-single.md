# Публикация: одиночная

Одиночная публикация — это отправка одной сохранённой генерации в выбранный домен. Доступна админам и менеджерам.

## Откуда запускается

В Single (`/create`):

1. Выберите промпт, заполните переменные, сгенерируйте.
2. Нажмите **Save**, чтобы сохранить результат.
3. Рядом с **Save** появится кнопка **Publish to…**.

Можно также открыть **ранее сохранённую генерацию** через окно **Saved generations** и опубликовать её оттуда.

## Окно публикации

Кнопка **Publish to…** открывает форму:

1. **Домен** — выпадающий список из настроенных в `/publish/domains`.
2. **Профиль** — если у домена WordPress и несколько профилей, выбирается профиль (например, «Статья» или «Лендинг»). Для Custom CMS этого пункта нет.
3. **Поля** — состав зависит от профиля или body-шаблона:
   - Для WP отображаются поля из выбранного профиля. Заголовок предзаполняется именем промпта, контент — текстом сгенерированного результата. Дополнительные поля (мета, таксономии, медиа) Вы заполняете вручную.
   - Для Custom отображаются плейсхолдеры из `body_template` домена.
4. **Язык** — если у домена больше одного языка.

После того как форма заполнена — кнопка **Publish**.

## Что происходит после нажатия

Запрос **не выполняется синхронно**. Система:

1. Создаёт `publish_job` со статусом `queued` и сразу возвращает результат.
2. В фоне Celery-воркер забирает задачу: переводит в `posting`, отправляет реальный HTTP-запрос в CMS, получает ответ.
3. При успехе — `posted` плюс ID и URL поста.
4. При ошибке — `failed` плюс текст ошибки.

Окно публикации **опрашивает статус** каждую секунду до 5 минут, пока не получит финальный результат. Можно закрыть окно — задача всё равно завершится в фоне; результат будет виден в `Published to` истории и в `/publish/post`.

## Лимиты и повторы

К каждому домену применяются лимиты, настроенные в `/publish/domains`. Если Вы за короткое время отправили десяток публикаций — они выполнятся последовательно, по очереди, чтобы не перегружать сайт.

При временных ошибках (429 или 5xx) система автоматически повторит запрос несколько раз с экспоненциальной задержкой. Параметры повторов настраиваются на уровне домена.

## Идемпотентность

Если Вы случайно нажали **Publish** дважды или обновили страницу во время публикации — второго поста **не появится**. У `publish_job` есть встроенная защита: повторный запуск той же задачи с тем же ID просто увидит, что статус уже `posting` или `posted`, и ничего не сделает.

## История публикаций для одной генерации

Когда Вы открываете сохранённую генерацию, под результатом отображается блок **Published to** — список всех публикаций именно этой записи: домен, профиль, статус, дата, ссылка на пост.

Это самый быстрый способ ответить на вопрос «куда уже улетал этот текст».

## Полная история одиночных публикаций

В `/publish/post` (в меню **Publish → Single Runs**) — список всех **одиночных** публикаций по всем пользователям. Записи от массовых прогонов сюда не попадают: они видны под своим прогоном на `/publish/runs/[id]` и нигде не дублируются.

### Удаление записей

В правом верхнем углу страницы — кнопка **Clear completed**: удаляет все одиночные публикации в терминальном статусе (`posted` / `failed`). Записи в работе (`queued`, `posting`) не трогаются.

В каждой строке справа есть **×** — удаляет одну запись (тоже только терминальные). Действие подтверждается окном `confirm` и необратимо. На массовые записи это не влияет — их можно удалить только с `/publish/runs`.

## Если публикация упала

Откройте запись в `/publish/post`. Вы увидите:

- HTTP-код ответа от CMS;
- тело ответа (часто там есть человекочитаемое сообщение);
- предупреждения, если они были (например, не удалось скачать картинку — пост всё равно опубликуется, но `featured_media` не появится).

Параллельно эта же ошибка попадёт в `/errors` с категорией `publish_error`. Там можно искать по полному тексту, фильтровать и сравнивать с другими сбоями.
